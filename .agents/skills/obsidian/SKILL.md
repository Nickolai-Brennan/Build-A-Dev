# Obsidian

1. Choose vault content editing or plugin development. Inspect the actual vault conventions, plugin manifest, minimum API version, and desktop or mobile targets.
2. Use supported Vault and Workspace APIs. Register events and cleanup through the plugin lifecycle. For note changes preserve frontmatter, link semantics, and existing files.
3. Build with the plugin's existing tooling and load it into a test vault. Exercise the command, reload/unload, and paths with spaces or duplicate note names when relevant.

Report the files changed, verification run, and any unavailable environment or access.
