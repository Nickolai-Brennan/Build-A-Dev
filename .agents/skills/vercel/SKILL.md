# Vercel

1. Identify team, project, framework preset, root directory, build command, runtime, and deployment target. Inspect effective configuration and distinguish Preview from Production.
2. Keep environment values scoped to the intended environment and reference names without showing secrets. Diagnose build and runtime failures from their actual logs.
3. Verify the changed route or asset on a Preview deployment. Before an authorized promotion, check the commit, target, smoke results, and previous deployment for rollback.

Report the files changed, verification run, and any unavailable environment or access.

[Product documentation](https://vercel.com/docs/deployments)
